# Context service implementation

Owned files: `host/context-service.mjs`, `tests/context-service.test.mjs`.

Implemented `createContextService({store,state,coordinator})` with `search(caller,{query,limit})`, `read(caller,{kind,id,beforeSeq,limit})`, and asynchronous `overview(caller)`.

- Authority binds to trusted `caller.channel || caller.chatKey`; a Router or operator role never enlarges event visibility. Public channels can read public groups (including WeChat groups) and public content platforms. Every other scope is exact-channel only. Host must supply source-scoped callers to Router tools.
- `search` returns `{events,truncated,nextBeforeSeq,coverage}`. Events include canonical `id`, `seq`, `kind`, `channel`, `threadId` (canonical channel), `actorId`, `at`, `text`, and `truncated`. Coverage explicitly states latest 2048 authorized events, first 4096 text characters. It does not claim full-history recall. The search response has at most 12 records, 512 text characters per record, and an aggregate serialized item budget of 11000 characters.
- Event references expand up to 4096 text characters; thread references use the exact canonical channel and return up to 12 events, 640 text characters each. Pages are newest first. Pass `nextBeforeSeq` back as `beforeSeq`; null means no additional returned-row page. Unknown, denied, empty, exhausted, or malformed references reject without broadening the query. `truncated` at envelope level describes omitted records; each event independently marks shortened text.
- SQL bounds rows and substrings before objects are loaded; no metadata, persona, memory-card scans, or full-history objects. Search uses a materialized candidate CTE so LIKE cannot search the unbounded journal. The fixed 2048-by-4096 candidate limit is approximately 8.4M characters before SQLite overhead; returned rows are separately much smaller. Exact reads use indexed event ID or channel/sequence.
- Task reads delegate `coordinator.knowledge(caller,{id,limit})` unchanged. Task result scoping/bounding is the coordinator's contract. Overview delegates `{limit:5}`, accepts either summary array or `{tasks}`, projects only id/state/summary, and caps serialized cards at 1900 characters. No added persona injection; existing recent context and conversation summaries remain untouched.

Verification: observed RED `ERR_MODULE_NOT_FOUND` before implementation, then GREEN. Latest `node --test tests/context-service.test.mjs`: 7 passed, 0 failed, ~2.7 seconds. Tests cover cross-public lookup, private/operator isolation without role bypass, exact source scope, event/thread paging and invalid references, long evidence/output bounds, task delegation, escaped overview budgets, and lookup of an older exact reference beyond the search candidate horizon. Local synthetic fixtures only (2051 max rows, 2.7M text chars in long-text fixture); no server operations or outbound effects.

Integration: import module in root-owned runtime, instantiate using runtime store/state/coordinator, expose context tools with trusted source caller, and document bounded search coverage. No runtime/index/guard changes made by this worker.

## Follow-up: development-result disclosure boundary

Root identified that public-channel `task.result` evidence can contain development results. Added a failing regression reproducing cross-group search/event/thread disclosure, then fixed all three paths. Cross-source ticket-bearing results now require an indexed `host_kv(kind='task-source',id=ticketId)` record with mode exactly `research`; development, missing mode, invalid metadata and unknown ticket records stay source-only. Same-channel reads remain available. Ordinary non-task evidence and public research results retain cross-public visibility. SQLite extracts only bounded metadata (32000 characters) and task-source JSON (4096 characters), never exposing either object. Thread candidate examination is bounded to 2048 records before cursor and reports that coverage; filtering occurs before the returned-row limit, so intervening private task results do not consume result slots. Search retains its prior 2048-candidate horizon.

Verification after fix: `node --test tests/context-service.test.mjs tests/context-tools.test.mjs` passed 11/11 (~2.7 seconds). This follow-up changed only context service/tests and this report.
