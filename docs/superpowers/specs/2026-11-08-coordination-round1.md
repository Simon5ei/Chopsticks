# Coordination round one — approved design

The user approved the seven-part architecture in this chat and explicitly requested implementation/deployment. Preserve existing Router hierarchy, platform sessions, identity, memories and tools. No new Router layers or SessionCross dependency.

1. Persist and deterministically gate inbound messages before any model call. Collect each original conversation's eligible messages for a fixed 3000 ms from the first arrival. New arrivals do not reset the deadline. Deduplicate, preserve actors/order/quoted-source metadata, restore pending windows after restart. Produce one semantic assessment and at most one conversational dispatch for a batch; a new message during processing belongs to the next batch. Administrator stop/cancel bypasses the wait.
2. Existing Router receives bounded active-task summaries and may read related task/source facts. Do not invoke overall Router merely because an event arrived when its domain is already determined.
3. Stable tasks can be discovered across public conversations. Related source discussion can become task context. Context never grants machine-operation authority. Private/operator/development task details remain scoped. Existing cancellation and source-bound outbound checks remain enforced.
4. A shared bounded context service supplies recent experiences and compact task references and can expand event/thread/task evidence on demand. No large new persona injection, no full-history scan.
5. New Worker identity follows task identity rather than assignment identity; adopt existing session mappings where present. Each new development task receives its own directory. Recover only provably idle/read-only interrupted work automatically; ambiguous deliveries/external command effects remain held, never replay blindly.
6. Deterministic task supervision checks stale progress/waiting/failure. It may request status or perform the permitted recovery once with durable cooldown/evidence; unresolved conditions become console attention records. No periodic model call for unchanged healthy state.
7. An authenticated pipeline view links source events, batches, Router decisions, tasks, tool calls and receipts. Show actual model calls/usage when supplied by DSH; unavailable usage is unknown, not zero. No fabricated internal reasoning. Keep existing relationship and mood pages.

Acceptance: batching timing/separation/restart/dedup/one-dispatch; cross-group research lookup and note without private/development disclosure or extra authority; stable task/session/cwd; recovery ambiguity and cancellation; references under budget; authenticated safe rendering; native DSH + real configured model with fake external adapters, no synthetic platform sends. Server diagnostics and validation must have explicit cgroup CPU/memory/time/process bounds.
