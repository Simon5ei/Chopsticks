# 可观测后台改造

**目标** 一条消息从进入到收尾，经过的每个关键节点都能在后台回答三个问题：这里用了哪段提示词、哪条规则做了什么决定、依据是什么。提示词和规则本身也要能在后台完整查到，且与运行时实际使用的是同一份。

**约束** 后台保持只读（心境模式切换除外），沿用 DSH 登录与 owner 校验，不新增监听端口、不引入前端依赖。所有新记录先过现有脱敏器，落在 `stateDir`，不进 Git、不进模型上下文。先写失败的回归测试；先在隔离 DSH 验证，部署是后续阶段。

## 现状（2026-11-13 核实）

后台有「设置 → 筷子」四个标签页（概览、事件链路、思考与工具、日志）和三个独立页（人际关系、心境、执行链路），共用 `POST /api/chopsticks-console` 的 7 个端点。数据来自 `events.sqlite`、`traces.sqlite`（7 天 / 2 万条，单条正文 8000 字符）。

缺口分三层：

1. **定义不可见**。所有提示词（`presets/runtime.patch.yml` 的 11 个预设前缀、外部 `persona.md`、`SOCIAL_REPLY_RULE`、约 40 条工具描述、十余处运行时拼装模板）和约 45 条规则（门控、配额、白名单、超时、范围）在后台都查不到。
2. **决定没落盘**。实际发给模型的提示词全文不记录；`meta.route=false` 不记原因；Router 每条动作的 `reason`、宿主对动作的改写、被静默跳过的动作都丢弃；工具被拒只留一句结果文本；回复票据的消费与拒绝无记录；配额拒绝只抛异常。
3. **展示是原始流水**。没有「这条消息为什么回 / 没回」的视图，任务、发送账本只有原始 JSON；三个独立页各自重写一套工具函数。

## 节点覆盖表

| 节点 | 现在能看到 | 改造后补上 |
|---|---|---|
| ① Trigger | `core_events` 一行 | 到达记录：来源适配器、是否去重命中；被 QQ 白名单丢弃的只计数，不存正文 |
| ② Thread / 门控 | 只有 `meta.route` 布尔值 | 门控决定及原因：休眠、唤醒间隔、摸鱼密度（含评估值）、策略拦截 |
| ③ Router | 决定种类、领域 / 平台理由、模型原生思考 | 本次拼装的提示词全文、预设与模型、每条动作理由、原始动作与改写后动作、被跳过的动作 |
| ④ 排入会话 / Ticket | `platform-job` 状态、`router.dispatch`、任务状态表 | 派发提示词全文、persona 版本、系统提示词追加段；任务提示词进入旅程视图 |
| ⑤ 消费来源后操作 | 工具调用与结果 | 票据签发 / 消费 / 拒绝 / 吊销；每条规则的放行或拒绝及原因码 |
| 只有内部文字？ | `delivery-*` 状态（仅 B 站私信） | 纳入旅程视图，标明适用范围 |
| ⑥ 回执 | `message.sent` 事件、`host_sends` | 发送账本页：sending / confirmed / not_sent / uncertain，回执 ID，幂等键 |
| turn/end | `turn.*`、`model.response` 用量 | 旅程末行给出结论：已发送 / 明确不回 / 未投递 / 未知 |
| 记忆、日记、心境、进化 | 各自状态表，后台只有心境和关系图 | 每次运行使用的提示词与来源集合；范围规则的决定 |
| 后台任务 / 开发任务 | 原始 JSON | 任务页：授权来源、worker 会话、执行过的命令（`command.execute`）、结果 |

## 设计

### 一、两个注册表（定义层）

**提示词注册表** `src/host/prompt-registry.mts`。每段提示词有稳定 ID、所属节点、来源（文件位置或外部路径）、类型（静态 / 配置 / 运行时拼装）和命名槽位。运行时调用点改为 `prompts.render(id, slots)`：返回文本，同时写一条 `prompt.rendered` 记录。注册表是产生提示词的唯一出口，后台读的就是它，因此不会与实际使用的文本漂移。

- 预设：启动时解析 `presets/runtime.patch.yml`，每个预设的前缀、guard 模式、插件列表成为条目。
- 外部文件：`persona.md`、`bili.config.json` 的相关段在查询时读取，显示内容、sha256、修改时间。
- 工具描述：从 `index.mts` 的注册和各 MCP 定义收集；按预设模式给出实际可见工具集合。
- 看不到的部分（DSH 自带的压缩提示词、外部 MCP 的描述）明确列为「外部，不可见」，不省略。

**规则注册表** `src/host/rule-registry.mts`。每条规则有 ID、所属节点、说明、参数及其来源（硬编码 / 配置键 / 外部文件）和当前生效值。调用点改为 `rules.decide(id, subject, outcome, reason, detail)`，写一条 `rule.decision`。有计数器的规则（配额、每日上限）同时暴露「已用 / 上限」。

### 二、决定落盘（运行层）

在 `traces.sqlite` 增加两张表，不改动现有 `traces`：

- `decisions`：小行，记录门控、Router、规则、票据的决定。字段含节点、规则 ID、结果（放行 / 拒绝 / 改写 / 延后）、原因码、事件 ID、请求 ID、快照 ID。保留 30 天 / 20 万条，按事件 ID、规则 ID、调用 ID 建索引。
- `prompt_segments`：按内容哈希存提示词分段。一次渲染记录为「槽位 → 哈希」列表，persona 这类长段只存一份。总量上限 64 MB，超出按最久未引用清理。

**运行快照**：进程启动时记录一次 `runtime.snapshot`（构建修订、预设文件哈希、persona 哈希、脱敏后的配置哈希、两个注册表的哈希），之后每条决定带快照 ID。提示词或规则改动后，仍能回答「当时这条消息用的是哪一版」。

**部署一致性**：构建产出文件哈希清单，启动时与已部署文件比对一次，后台显示不一致的文件和残留的 `*.bak-*`。11 月 13 日开发 worker 原地修改线上文件、随后被整树部署覆盖而无人察觉，这一项就是针对它。

### 三、后台结构（展示层）

合并为一个独立站点，共用一套外壳（导航、RPC、时间、JSON 查看、关联跳转、表格与时间线组件）。「设置 → 筷子」面板保留为摘要入口。

1. **总览**：按逻辑流程图排列的节点看板，每个节点显示近一小时通过 / 拦截 / 进行中 / 未知的数量，点击进入筛选后的列表。
2. **消息旅程**：按事件 ID、频道、时间、文本查找。单条消息固定展示七行节点，每行给出状态、触发的规则决定、实际发出的提示词（可展开，分段并标注来自哪个模板）、模型思考与输出、工具调用。顶部一句结论，例如「未回复：Router 判定 observe，理由……」或「被规则 `social.comment-hourly-cap` 拒绝（10/10）」。功能启用前的旧消息对应节点标「未记录」。
3. **提示词**：按节点分组的注册表。每条显示当前文本、来源、类型、槽位、哈希、最近渲染（可跳到旅程）。另有「按预设查看最终拼装」：前缀、系统提示词追加段、该模式可见的工具描述。
4. **规则**：按节点分组。每条显示说明、参数与来源、实时计数器、24 小时放行 / 拒绝统计、最近决定。附「预设 × 工具」权限矩阵，由 `guard.mts` 的集合生成。
5. **任务**：Ticket、Worker 会话、开发任务（授权事件、执行过的命令、结果）、监督记录；进化、日记运行。
6. **发送账本**：`host_sends` 全量状态，uncertain 置顶并提示不得重发。
7. **系统**：运行快照、部署一致性、生效配置（脱敏）、各表保留情况；心境、人际关系、内容回顾并入导航。

新增只读端点：`nodes`、`journey`、`prompts`、`prompt`、`rules`、`rule`、`tasks`、`sends`、`system`。每个端点校验入参、限制条数与响应大小，查询只走索引。

### 四、防止回退

加一条结构测试：扫描 `src/` 中直接向模型发送模板字符串的调用和直接拒绝的门控，凡未经注册表的即失败。新增提示词或规则时必须注册，否则测试不过。

## 步骤

1. **基础**（已完成，2026-11-13）。回归测试：决定表与分段表的写入、去重、保留清理、脱敏；快照记录。实现两张表、快照、两个注册表骨架。不改界面，也不改运行时行为：`decision-log.mts` 挂在 `createObservability().decisions` 上，`prompt-registry.mts`、`rule-registry.mts` 尚无调用点。
2. **提示词可见**（已完成，2026-11-13）。`runtime.mts` 创建两个注册表实例，`start()` 时记录运行快照。宿主自己写的提示词全部集中到 `src/host/prompts.mts`，调用点只给槽位值：Router 三段、派发、三种平台协议、日记、任务输入与 Worker 提示、开发请求、进化回顾、心境证据与表达、系统上下文。预设前缀、persona、宿主注册的工具描述接入注册表。上线「提示词」页（`/api/chopsticks/prompts`）和 `prompts`、`prompt` 两个只读端点。
   - 字面文本逐字迁移：迁移后用脚本核对了目录里 81 段固定文本，全部能在迁移前的源文件中原样找到；每段提示词另有与旧模板逐字比对的回归测试。
   - 注册表在第 1 步的基础上增加了四样：按名字选择的固定分支（`options`）、引用已注册的固定文本（`include`）、可选槽位的后缀、可嵌入上级提示词且保留分段的片段（`fragment`）。这样一次渲染的记录能分清每一段是固定文本、配置还是当时的数据。
   - 系统上下文每个模型步骤都会重建，只在文本对该会话发生变化时记录一次。
   - **本步未覆盖，页面上已明确列出**：DSH 内置系统提示词与压缩提示词；外部 MCP 的工具描述；平台 MCP（`src/life/mcp.mts`）的 status / read / write 描述；宿主合成的事件正文（定时器、提醒、阅读证据等 8 处，它们作为事件数据进入上下文）。后两项可以接入，留到第 4 步的结构测试一并处理。
   - 运行快照目前含版本号、两个注册表哈希、persona 哈希、预设哈希、脱敏后的配置哈希；构建修订号等第 5 步的部署一致性清单一起加入。
3. **规则可见**。给入站门控、Router 策略与改写、guard 拒绝、回复票据、社交配额、发送门控、各平台每日上限接上 `decide`。上线「规则」页和权限矩阵。
4. **消息旅程与总览**。实现 `journey`、`nodes` 端点和两页；共用外壳落地，旧的事件链路 / 执行链路页改为跳转。
5. **任务、发送账本、系统**。含部署一致性。更新 `docs/guides/console.md`。
6. **验收**。类型检查、全套回归、结构测试。隔离 DSH 加真实模型跑一条群消息、一条私信、一次浏览轮、一个后台任务，逐条确认旅程七行节点都有记录且提示词全文可查。服务器上的检查按资源限额执行。

每一步可独立合入和部署，前一步不依赖后一步。

## 不做的事

- 不在后台编辑提示词或规则。提示词仍在 Git 和外部 persona 文件里改，后台只读。
- 不记录被 QQ 白名单丢弃的消息正文。
- 不做逐 token 流式展示，不补写模型没有输出的思考。
- 不改动现有事件库、原生会话历史和 `traces` 表结构。

## 待定项（已给默认值）

- **私有文本全文展示**：默认在后台显示 `persona.md` 等外部文件全文，仅 owner 可见。
- **保留与磁盘**：决定 30 天 / 20 万条，提示词分段 64 MB。服务器磁盘紧张可下调。
- **迁移范围**：`src/bili/commands/` 下以子进程运行的 B 站 CLI 门控（`limits`、`free-gate`、`quota-gate` 等）把决定写在外部账本里，第 3 步先在规则页列出定义和参数，决定接入留到之后。
