# Bili command extraction

源码位于 `src/bili/`。下列 `node bili/...mjs` 命令需在编译产物目录 `dist/release/`（生产环境为 `/opt/chopsticks`）内执行；从仓库根目录执行时请加上 `dist/release/` 前缀。

The runtime module in `src/bili/` contains the fixed command dependency closure of nine Bili MCP tools from the MIT-licensed SurfCore/QSH source. The original notice is in `../../notices/surfcore-bili-LICENSE`. No installed SurfCore, old plugin host, UI, updater, voice runtime or SessionCross is imported. `lib/identity-guard.mjs` is the upstream pure identity guard, moved into this closure.

Start the private stdio server with `node bili/mcp/server.mjs`, or import `createBiliService` from `bili/mcp/service.mjs`. Runtime dependencies are Node >=24, the root project's MCP SDK and Zod; frame extraction additionally needs a separately installed ffmpeg (`FFMPEG`, PATH, or the external account's `bili/bin/`). No ffmpeg binary is distributed.

Required external data configuration:

* `CHOPSTICKS_FISH_HOME`: absolute fish data root, e.g. `/var/lib/chopsticks/fish`. It contains `characters/current.json`, `characters/<id>/character.json`, role-specific `characters/<id>/bili/` history/ledgers, account-level `bili/credentials.json`, and `bili.config.json`. There is no implicit `surfcore` suffix. An existing legacy data directory can be selected explicitly during migration; the installed legacy code is never consulted.
* `CHOPSTICKS_BILI_CONFIG`: optional absolute configuration file override; otherwise `<fishHome>/bili.config.json`.
* `CHOPSTICKS_BILI_CREDENTIALS`: optional absolute credentials override; otherwise `<fishHome>/bili/credentials.json`. Keys are `sessdata`, `bili_jct`, `buvid3`. Never place this file in Git.

Service options `fishHome`, `biliConfig`, `credentialsPath` override these environment settings. `call(name, args, trustedCaller)` retains the existing API. Trusted caller fields are `role` (`operator` or `bili`), `canWrite`, `sessionId`, optional `characterId` and `signal`. Reads do not need write authority. Stdio calls carry this host-generated context in `_meta.chopsticksCaller`; model-facing schemas contain no authority fields. This transport is a private child of the trusted host, not an authenticated multi-user endpoint. `commands/` is an internal CLI closure, not an additional model tool surface.

The tools are `bili_video`, `bili_search`, `bili_subtitles`, `bili_comments`, `bili_dynamic`, `bili_history`, `bili_frames`, `bili_comment`, and `bili_dynamic_post`. Only the final two publish, require trusted authority even for dry previews, and default to dry mode. Non-operator writes append the original `--auto` guard flag. Fish flooding/gathering, comment cooldowns and daily limits, pending-attack checks, identity guards and quota-corruption rejection remain. A failed fish inspection now blocks autonomous commenting. A successful comment no longer triggers hidden likes or arbitrary notification commands/webhooks; the host receives its receipt and owns notification policy. The legacy quota gate does not impose a daily count on ordinary text dynamics; the host still owns standing-rule authorization. Dynamic successes record their quota ledger entry. Both publishing commands require a configured `self.mid` matching the authenticated account. Video comments resolve the supplied BVID and require its returned aid to match the supplied oid before posting. `dynamics.enabled=false` blocks dynamic publishing, and autonomous dynamics enforce `dynamics.gapMin` against both new quota records and the migrated `daily-dynamic.json`; unreadable cooldown state fails closed.

Writes are serialized within one service instance. API code 0, successful HTTP status and a valid returned publishing identifier produce a private receipt artifact, surfaced as `structuredContent.receipt = {status:'confirmed', kind, id, url}`. Console text cannot forge a receipt. A receipt confirms platform acceptance, not anonymous visibility/moderation status. Missing identifiers, transport errors and timeouts yield an uncertain result with no retries; verify platform state before any retry. Use one production owner. Credentials and local paths are scrubbed from model-facing text; history exposes only public watch metadata. Artifacts are bounded, returned as real image bytes, then removed. Fetches and redirect hops are restricted to Bili/API/CDN HTTPS destinations, with credential stripping on media hosts.

## One-cycle feed proposal

`createFeedProposal({fishHome,biliConfig,credentialsPath})` from `bili/feed.mjs` returns an async function accepting `{limit:6, source:'all', signal}`. Limit is 1–12; source is `all`, `search`, `popular`, `rank`, or `following`. It returns `{source:'bili', kind:'feed-proposal', items:[{bvid,title,up,url}]}` and does not publish or modify feed-picks. The extracted feed algorithm uses configured `preferences.like`, `preferences.keywords`, and `preferences.weights`, excludes watched/recently proposed material, and keeps preference/history details out of its result. The host must scope these proposals to the Bili worker; candidate selection can still reflect private preferences even when the returned fields describe public videos.

No autonomous scheduler is copied: the old scheduler depends on the discarded plugin host. The host schedules this callable cycle under an explicit standing rule, stores observations, and asks its model to decide whether to inspect/respond. A timer event alone is not write authorization. Since proposals do not write feed-picks, the host should deduplicate candidate events or update its own canonical event journal.

## Social inbox and private replies

`adapters/bili-social.mjs` polls reply/mention notifications and bounded private-message history under the existing external `bili.config.json.listen` settings. It keeps exact platform IDs, verifies comment floors, skips persisted notification keys, and reports partial scans. The host seeds the first listener baseline without replaying old conversations, then persists each new received event before marking it seen. No platform read acknowledgement is sent by polling.

`chopsticks_bili_reply` replies to the current consumed public comment event; the model supplies text only. Video and dynamic comment targets are separately verified, including dynamic comment types 11/17. `chopsticks_bili_dm_reply` is restricted to a dedicated `bili:dm:<mid>` session and the current received peer. Private events and memories are excluded from groups, public Bili and other private conversations. The adapter rechecks the latest inbound message before a single POST; a stable server `msg_key` is required for confirmation. Uncertain sends are not retried. Daily private replies are bounded at 30 total, with at most three to each non-owner peer.

Feed scheduling uses Asia/Shanghai for both date and window time. Empty feed results do not consume an opportunity. Health includes the feed waiting/error reason, daily consumption and social-inbox partial/error state, rather than treating service readiness as proof of successful Bili activity. All publishing remains disabled in isolated validation unless its transport is explicitly replaced in the private validation copy.

Verification uses temporary fish fixtures, simulated Bili HTTP responses, real subprocess execution, and a real MCP SDK stdio client. It does not read live fish data or post to Bilibili.
