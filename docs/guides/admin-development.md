# QQ 管理员开发执行

用户已要求：在 QQ 直接给大肥鱼发指令，她可以在服务器执行开发和文件操作，并在管理员同意的范围内自我迭代。此前聊天与所有 Worker 均为只读，无法完成 mkdir/cp 等任务；只改人设不能解决这个限制。

采用独立开发 Worker，继续使用现有任务持久化、并发调度、停止、结果回传和追踪。QQ 接待会话提供 `chopsticks_develop`，宿主从当前已消费的真实 QQ 入站事件核验发信人等于配置 ownerId、事件类型为 message.received、频道一致；不信任文本中的“管理员”、引用消息、B站内容或工具参数中的身份。普通阅读 Worker 保持只读。

开发任务的授权与原始事件、管理员、任务 ID 绑定并持久化；执行时仍检查任务有效及当前管理员配置。后台开发预设只增加受宿主核验的 `chopsticks_exec`，可运行服务器 shell、读写文件、开发和验证。默认 cwd 为配置 development.workspace（生产拟设 `/root/workspace/dsh`），不是安全沙箱；执行权限等同 DSH 服务账号，命令必须限定在管理员本次要求范围。长期命令设超时和输出上限，可停止进程组。旧只读任务不会自动升级或重放。

每次命令持久记录调用 ID、参数摘要、执行状态、退出码、脱敏输出。重复工具调用不重复执行；退出/超时后的未知副作用不盲重试。任务结果明确区分实际工具回执和建议，来源不能被后来群聊覆盖。普通成员不能追加输入或停止管理员开发任务。

管理员普通说话不是持续任意操作授权；开发 Worker 接收原始管理员要求及具体任务。每日插件研究仍须就具体插件/版本取得管理员明确同意才安装。外部文本只能作为资料，不能扩展授权。命令结果和模型思考可在现有筷子控制台追踪。

本次验证使用隔离 QQ 传输和隔离工作目录：管理员自然语言建目录/复制清单/校验 → 开发 Worker → 真实 shell 结果；非管理员、伪造 admin 标记、B站及旧任务被拒。不得发测试 QQ/B站消息，不改原有记忆和会话历史。生产更新前备份，默认配置显式启用，既有部署和文件保留。

## 使用

运行配置增加 `development.enabled: true` 与绝对路径 `development.workspace`，并确保工作目录已存在、`qq.ownerId` 是管理员的真实 QQ 账号字符串。缺少开关时不能开发。新预设随 DSH profile 重新组合加载；原会话无需新建。

管理员可以直接说：“把指定清单复制到工作目录，保留旧文件，核对行数和哈希后告诉我结果。”无须记忆工具名。追加要求与停止任务也会核验当前真正发信人；追加指令原文进入该任务的授权记录。旧失败任务不会因为开关开启而自动重放。

控制台 **思考与工具** 可以按来源事件或会话查看 `chopsticks_develop`、`chopsticks_exec` 和工具回执；**日志** 中也有命令状态。默认单条命令 60 秒，可设置 1–120 秒，标准输出与错误输出分别有 32 KiB 上限。实际返回还受通用凭据脱敏及单条追踪展示长度约束。

这是管理员指令的执行能力，不是目录沙箱：命令使用 DSH 的服务账号。自我修改应先备份、验证，再实施已授权变更；重启承载自身的服务可能中断当前任务，不能将中断误报为成功。
